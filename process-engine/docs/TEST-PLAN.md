# Process Engine: Test Plan

Every statement in [`SPEC.md`](SPEC.md) has at least one automated test whose name starts with the statement's test id (`TR-QA-01`). A CI script lists the statement ids in `SPEC.md` and fails when a test with that id prefix is missing for a statement whose milestone has been reached. The script is `tools/spec-coverage.py`, run by the CI job "Spec-to-test coverage"; it reads the statement ids in `SPEC.md`. Statements not delivered yet are listed with their milestone in [`spec-pending.txt`](spec-pending.txt). The gate fails on any entry whose milestone is at or before the current milestone in `tools/spec-coverage.ini`, and warns when an entry already has a test; the pull request that adds the test removes the line. Only running tests count: disabled, skipped, `todo` and commented-out tests do not.

## Strategy
| Layer | Tool | Scope | Gate |
|---|---|---|---|
| Unit and property | JUnit 5, AssertJ, the project's seeded generator (PD-090) | Lifecycle guards, graph diff, RFC 8785 canonicaliser, calendar arithmetic, BPMN reader | Every pull request |
| Storage contract | Shared suite | In-memory and PostgreSQL adapters | Every pull request |
| Integration and fault | Testcontainers, Toxiproxy | Two replicas, paused claimants, 2-connection pool, failover, rollup, partitions | Every pull request (PostgreSQL 16), nightly (full matrix) |
| Query plans | `EXPLAIN (FORMAT JSON)` on a seeded database (1 million instances, 20 million history rows) | Every registered list query (`TR-PERF-07`) | Every pull request touching `process-engine-postgres` |
| Contract | WebMvc tests, OpenAPI diff, JSON Schema | Every error code in the DESIGN REST table; event schemas | Every pull request |
| Architecture | ArchUnit | Core boundaries; adapter ports never called inside a transaction | Every build |
| Load | Load harness on the dedicated runner | `TR-PERF-04`, `TR-PERF-08`, `TR-PERF-09` | M2 exit, then per release |

Cancellation under PD-103 (`PRE-054`) is proven by `ProcessRestApiIT.PRE_054_*` and `QueryLimitsTest.PRE_054_*`: a caller with `processes:start` only gets `403`, a holder of `processes:cancel` cancels with a reason recorded on the history row and the event, the cancel enters no step and runs no compensation, a missing, blank or 2,001-character reason is `400`, and `/api/bpm/me` lists the permission only for its holders.

The completion API of remote steps is covered at two levels. `AsyncWaitStateTest` (Java API, Testcontainers): `TR_ASY_02_*` refuse a derived attempt id without its completion token, a token of another job and a token of an earlier attempt, and check that only the token's SHA-256 is stored and that `AdapterCall.toString()` masks it; `TR_SEC_04_a_client_scoped_to_another_adapter_cannot_complete_a_bureau_step` refuses a caller whose role is listed for another adapter; `TR_IDEM_04_a_retry_after_a_timeout_sends_the_same_idempotency_key` checks that a retry after a timeout keeps the job id as idempotency key. `AsyncStepCompletionIT` in `examples/rule-and-process` (host over HTTP): `200 ACCEPTED` and the loan moves on, a repeat is `DUPLICATE`, another tenant is `404` with nothing written, `403` without the permission, with a role of another adapter or with a wrong token, and `400` without a token or without `errorCode`. `TrackedTransactionRunnerTest` checks that the adapter-outside-transaction guard sees the engine's transactions with a non-Spring runner (`TR-ASY-01`).

The result check of #363 (`PRE-058` to `PRE-060`) is tested on the result transaction itself: `RunnerPerKindIT` parks the step as a remote step and turns its job into an `ASYNC_AGENT` job with a guard spec of its choosing, including specs the agent step never writes (none, or `fourEyes: false`), and a stub agent runner answers it. The agent step of #52, which writes the spec from the published definition and runs on the agent runner, is covered by `AgentTaskIT` (`PRE-061` to `PRE-063` and the agent cases of `PRE-009`, `PRE-017` and `PRE-041`) and end to end by `GuardedAgentTaskIT` (`PRE-010`).
